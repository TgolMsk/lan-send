# 0008. 断点续传（私有扩展）

- 状态：已接受
- 日期：2026-09-07

## 背景

大文件在 Wi-Fi 上中断后整文件重传代价高，iOS 后台回收 socket 时尤甚。官方协议没有续传；扩展必须对官方客户端不可见。用户已决定：只在双方都声明 `resume` 时启用；断点状态 24 小时有效，会话结束即失效。

## 决策

1. **能力声明**：`x-lanext.features` 含 `"resume"`。发送方在 `prepare-upload` 的 `info` 里声明，接收方据此决定是否附带续传字段；接收方的能力来自发现阶段拿到的 `x-lanext`。
2. **响应字段**（仅对声明了 `resume` 的发送方）：`prepare-upload` 的 200 响应附加 `x-resume-token`（本会话随机令牌）和 `x-resume-offsets`（`{fileId: 已收到字节数}`，只列出大于 0 的）。官方客户端忽略未知字段。
3. **上传**：`POST /upload` 可带 `Range: bytes=<offset>-` 与 `x-resume-token` 头；服务端要求 offset 等于 `.part` 文件当前长度，否则回 416 并在 `x-resume-offset` 头给出实际长度；开启校验时先对已有前缀重新哈希再追加。无 `Range` 的上传照旧从零开始（截断）。
4. **断点查询**：`GET /api/ext/v1/resume?sessionId=&fileId=`，带 `x-resume-token`，返回 `{"offset": N}`；只对会话的发送方 IP 有效，文件正在上传时回 409。
5. **会话内恢复**：对声明了 `resume` 的发送方，传输中断（非 4xx 错误）不把文件标为失败，而是回到待上传，保留 `.part`（最多 3 次尝试）。发送方查询断点后带 `Range` 重传。
6. **跨会话恢复**：接收方把未完成的 `.part` 记入 `partial_uploads`（发送方指纹、sha256、大小、最终路径、已收字节）。新会话到来时按（指纹、sha256、大小）匹配，把最终路径固定为原路径并在响应里给出 offset。24 小时未更新的记录连同 `.part` 一起清除；会话结束时对应的 token 失效。
7. **闲置回收**：任何会话 10 分钟没有请求即被回收（`SessionEnd { TimedOut }`），避免发送方消失后单会话槽被永久占用；跨会话恢复覆盖它回来的情形。
8. **身份**：所有续传操作都在 mTLS 之上，且校验会话发送方 IP 与 token；token 本身不是唯一凭证。

## 备选方案

- 每个分片单独请求（分块上传）：需要改会话模型，官方客户端无法兼容，放弃。
- 用 sha256 之外的内容标识（文件名 + mtime）：不同内容会被误判续传，放弃。

## 后果

- 续传要求发送方提供 sha256；关闭校验和的发送方只能在会话内按 offset 恢复，跨会话不匹配。
- 接收目录里的 `.part` 文件可能保留最多 24 小时。
