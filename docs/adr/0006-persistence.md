# 0006. 持久化：settings.json 与 SQLite

- 状态：已接受
- 日期：2026-09-07

## 背景

里程碑 2 需要传输历史、收藏/信任设备、断点续传的未完成上传记录，以及可编辑的设置。简报要求设置用 JSON、历史与信任用 SQLite（`rusqlite` bundled，schema 版本化、启动自动迁移）。

## 决策

1. **设置** `settings.json`（配置目录，camelCase，缺省字段取默认值，未知字段忽略）。命令行参数覆盖设置，设置覆盖默认值。默认值：端口 53317、强制客户端证书、接收目录 = 系统下载目录、不分子目录、同名追加 ` (n)`、生成并校验 sha256、并行上传 3、跳过隐藏文件、历史 200 条、启用续传。
2. **数据库** `lan-send.sqlite3`（数据目录），WAL 模式，`PRAGMA user_version` 记录 schema 版本，`Database::open` 逐版本迁移。v1 三张表：
   - `devices`：按指纹为主键，保存别名、自定义别名、型号、最近地址、`favorite`、`paired`（里程碑 3 用）、首次/最近见到时间。
   - `transfers`：每个文件一条，方向、对端、文件名、本地路径、大小、MIME、状态、错误、起止时间。超过 `historyLimit` 时删最旧。
   - `partial_uploads`：未完成上传的 `.part` 文件，按发送方指纹 + sha256 + 大小匹配，供续传；超过 24 小时清除。
3. 数据库 API 是同步的（`parking_lot::Mutex<Connection>`），写操作都很小；需要时调用方用 `spawn_blocking`。
4. 核心库只负责读写，"何时记录"由应用层（CLI / Tauri）在事件里调用同一组 API，避免两套逻辑。
5. 发现模块启动时探测收藏设备与最近 7 天见过的设备的已知地址，按指纹匹配结果，不信任 IP。

## 备选方案

- 全部用 JSON 文件：历史会增长、并发写不安全，放弃。
- `sqlx`/异步驱动：引入运行时耦合与编译开销，收益为零，放弃。

## 后果

- `rusqlite` bundled 会把 SQLite 编进二进制（约 1 MB），iOS 交叉编译无额外依赖。
- schema 变更必须新增迁移步骤，禁止改旧步骤。
