# 0016. 多语言：八种界面语言、原生层与错误编码

- 状态：已接受
- 日期：2026-09-13

## 背景

里程碑 6 的前端只有中英两张内联表，语言偏好存在网页端的 localStorage，托盘菜单、文件对话框标题、iOS / macOS 的系统权限弹窗只有英文，Rust 层的错误原文直接显示在提示里。产品决定第一批支持简中、繁中、英、日、韩、德、法、西八种语言，并且原生层与错误提示一并本地化，商店文案也要有对应语言。

## 决策

- **文案表**放在 `apps/app/src/locales/<locale>.json`，英文表定义键的类型并作为回退；`scripts/check-locales.mjs` 在 `pnpm build` 前校验键集合与占位符一致。
- **语言偏好**是核心设置 `app.language`（`system` 或所支持的 BCP 47 标签），前端与 Rust 侧共用同一套“标签 → 语种”的解析规则（`zh-TW/HK/MO/Hant` → 繁中，其余 `zh` → 简中，其它按主语言）。localStorage 只作首屏缓存。
- **原生层**：托盘菜单在运行时就绪后按设置重建，文件对话框标题按设置取；系统权限弹窗用 `apps/app/src-tauri/locales/<locale>.lproj/InfoPlist.strings`，macOS 通过 `bundle.resources` 放进 `Contents/Resources`，iOS 通过 `project.yml` 作为资源加入。
- **错误编码**：核心层新增 `runtime::ErrorCode`（kebab-case 序列化），从 `ClientError` / `io::Error` / HTTP 状态归类；`TransferView.error_code`、`PairResult.code`、`Error.code` 与 IPC 的 `AppError.code` 携带它，前端按 `error.<code>` 键翻译，没有编码的保留英文原文。
- **不做**：Windows 安装包的多语言、CLI 的多语言、历史记录里旧错误文本的翻译。

## 备选方案

- 用 i18next / react-intl：多一层运行时与依赖，现有 `t(key, vars)` 已够用，复数在本应用里只有“{n} 个”这类可用占位符规避的情况。
- 在 Rust 层翻译错误消息：核心库要为此承载语言表，违背“核心无 UI 语言”的分层；编码由界面翻译更轻。

## 后果

- 正面：加语言只需新增一个 JSON 与一个 `.lproj`，CI 能挡住漏译；错误提示对非英语用户可读；权限弹窗跟随系统语言。
- 负面：机器翻译的六种语言需要母语者复核；每次新增错误来源要记得归类到 `ErrorCode`，否则回落到英文原文。
