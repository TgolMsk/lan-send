# 0003. 设备发现

- 状态：已接受
- 日期：2026-09-07

## 背景

官方 1.18 的发现是"UDP 只发公告、HTTP register 回应"，多网卡机器需要每个接口一个 socket，而 iOS 与部分网络没有组播，必须有 HTTP 扫描回退。

## 决策

1. 组播：每个非回环 IPv4 接口地址绑一个 UDP socket（`SO_REUSEADDR` + Unix 下 `SO_REUSEPORT`，绑 `0.0.0.0:53317`，`IP_ADD_MEMBERSHIP` + `IP_MULTICAST_IF` 指定接口，loopback 开、TTL 1）。一次 announce 发 3 个报文（+100/+500/+2000 ms）。IPv6 留到里程碑 2。
2. 收到公告：忽略自己的指纹；用**固定到公告指纹**的客户端向 `来源IP:port` 发 `POST /register`；成功后设备入库并广播事件。UDP 永不回应。
3. 分级扫描：announce 与"探测已知地址"并行；若 1 s 宽限期内没有任何确认，再对每个本机接口的 `/24` 全量 `register`（并发 50，超时 500 ms）。
4. 组播绑定失败不是致命错误：记录原因，其余手段照常工作。
5. 设备库按指纹去重，保存最近一次可达的地址；服务端收到的 `register`（对方主动注册）由应用层回灌到设备库。
6. 事件通过 `tokio::sync::broadcast` 对外暴露，不做任何 UI 假设。

## 备选方案

- 单 socket 绑 `INADDR_ANY` 发送：只会走默认路由的接口，多网卡时其他网段收不到，放弃。
- mDNS/Bonjour：官方不支持，放弃。

## 后果

- 同一台机器上多实例可互相发现（loopback 开启），便于本机互操作测试。
- 子网扫描会瞬时打开数百个连接，服务端 accept 循环要容忍资源类错误。
