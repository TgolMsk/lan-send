# 0009. IPv6

- 状态：已接受
- 日期：2026-09-07

## 背景

官方 1.18 在 v2.2 之上扩展了 IPv6：组播组 `ff12::fd3a:e420`（链路本地范围），HTTP 服务同时监听 v4/v6。仅 IPv6 的网络（部分企业/校园网、IPv6-only 热点）没有它就无法发现设备。

## 决策

1. **组播**：除每个 IPv4 接口地址一个 socket 外，每个有 IPv6 地址的接口再建一个 `IPV6_V6ONLY` socket，按接口索引加入 `ff12::fd3a:e420`，`IPV6_MULTICAST_IF` 指定接口，hop limit 1，loopback 开。公告在两族上并行发送；同一设备从两族收到时按指纹去重。
2. **服务端**：在 `[::]:port` 再绑一个 `IPV6_V6ONLY` 监听（macOS 默认双栈会与 v4 监听冲突）；绑定失败只记录，不影响 v4。
3. **链路本地回拨**：来源是 `fe80::/10` 时必须带 scope（接口索引）才能连回。地址以 `ip%scope` 形式保存在设备与目标里；HTTP 客户端把它编码成内部主机名 `fe80--1s3.scoped.lan-send.internal` 交给自定义 DNS 解析器还原成带 scope 的 socket 地址（与官方实现同一思路）。证书校验本来就忽略主机名，不受影响。
4. **子网扫描**只对 IPv4；IPv6 靠组播、已知地址与对方注册。
5. 设置 `ipv6`（默认开）可整体关闭 IPv6 组播与监听。
6. 命令行目标支持 `[fe80::1%en1]:53317`，接口名会换算成索引。

## 备选方案

- 只支持全局/ULA 的 IPv6：绝大多数局域网只有链路本地地址，放弃。
- 双栈单 socket：macOS 上与 v4 socket 冲突，官方也不这么做，放弃。

## 后果

- 同一设备可能被记录两个地址，设备库以最近确认的为主并保留全部地址。
- 在没有 IPv6 的网络上多出的 socket 只是空转。
