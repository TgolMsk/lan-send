# 0022. macOS 菜单栏图标拖放发送

- 状态：已接受
- 日期：2026-10-18

## 背景

用户希望在 macOS 上把文件拖到顶部菜单栏的 LanSend 图标上，图标下方弹出设备列表，拖到某台设备上松手就直接发送。不必先打开主窗口、再选设备。

约束：菜单栏图标由 Tauri 的 `tray-icon` 创建（`NSStatusItem`），Tauri 没有提供拖放接口；最低系统 macOS 12；Mac App Store 版本运行在沙盒里。

## 决策

1. **图标接收拖放**：通过 `TrayIcon::with_inner_tray_icon` 取得 `NSStatusItem`，对按钮所在窗口调用 `registerForDraggedTypes([public.file-url])`，并把窗口的 delegate 设为自定义的 `LanSendTrayDropTarget`（objc2 `define_class!`）。该窗口里没有视图注册拖放类型，AppKit 会把拖放消息交给窗口 delegate 处理。代码在 `src-tauri/src/platform/macos_tray_drop.rs`。
2. **设备面板**：一个隐藏的 Tauri 窗口 `tray-drop`（无边框、置顶、所有桌面和全屏应用上都可见、不抢焦点、首次点击即生效），加载 `index.html?panel=tray-drop`，渲染 `panels/TrayDropPanel.tsx`。文件拖进图标时，把面板放到图标正下方再显示；面板用 Tauri 自带的 webview 拖放事件按坐标找到设备行，松手后调用 `cmd_transfer_send`。
3. **产品规则**（2026-10-18 用户确认）：
   - 面板列出全部在线设备，收藏和已配对的排在前面；发送不要求先配对。打开面板时顺带重新探测一次网络，设备上线或离线会实时更新列表。
   - 直接在图标上松手：面板留住并显示「已选 N 项」，点选设备即发送；点到别的应用或 30 秒无操作就收起。面板不成为 key window（否则会激活应用），点到外部这件事靠一次性的全局鼠标监听发现。
   - 发出后面板显示「正在发送给 X」，随即收起，不弹出主窗口；传完用系统通知报告结果（成功、失败、被拒绝；用户自己取消的不报告），受「系统通知」开关控制。例外：对方要求 PIN 时，主窗口会自动显示 PIN 输入框，因为没有别的地方能输入。
   - 设置 › 应用里有「把文件拖到菜单栏图标上发送」开关（`app.menuBarDrop`），默认开启，只在 macOS 显示。关掉时拖到图标上会被拒绝，并销毁面板以释放网页进程。
4. **通知实现**：`tauri-plugin-notification`，只作为 macOS 依赖，只用它的 Rust 接口（`cmd_app_notify` → `platform::notify`），所以不需要给前端开插件权限，Windows 和 iOS 的构建也不受影响。
5. **坐标单位**：macOS 上 wry 给出的拖放坐标是逻辑点，Tauri 的类型却标成物理像素，前端不能再除以 `devicePixelRatio`。主窗口「拖到设备卡片直接发送」原先在 Retina 屏上除错了，这次一并修正（`store.ts`）。

## 已验证（2026-10-18，macOS 26.6.2，调试构建，非沙盒）

- macOS 26 起，菜单栏上第三方图标的窗口由「控制中心」进程托管，应用自己的状态栏窗口在屏幕外。即便如此，拖放仍能转发到应用。
- 用 CGEvent 模拟真实拖拽，以下路径都通过：拖到图标再投到设备行（文件到达本机 CLI 接收端，SHA-256 一致）；拖过图标后移走（面板自动收起）；直接投到图标再点设备（文件到达，应用不需激活）；投到图标后点别的应用（面板收起，不发送）；开关关闭时拖放被拒绝；运行中开、关开关立即生效；隐藏主窗口时对方要求 PIN，主窗口自动显示 PIN 输入框。
- 发送完成后系统弹出 LanSend 的通知授权请求，说明通知已送达系统；授权后通知的实际显示要由用户确认。

## 未验证 / 风险

- macOS 12–15：这是经典的 `NSStatusBarWindow` 做法，按理可行，但本机没有旧系统，未实测。
- Mac App Store 沙盒构建：从 Finder 拖进来的文件按系统规则会获得读取授权，未实测。
- 多显示器（每块屏幕各有一条菜单栏）、菜单栏被收起或被 Bartender 一类工具隐藏的情况。
- 关掉开关时面板的网页进程会释放，但 tao 会留下一个已关闭的空 `NSWindow`；只有反复切换开关才会累积，影响可忽略。

## 备选方案

- 拖到 Dock 图标：系统原生支持，但只能松手后再弹窗选设备，拖动途中无法选择，不符合需求。可以作为补充入口。
- 访达「共享」扩展 / 「服务」菜单：要额外建 App Extension target，Tauri 工程不好集成，交互也是先松手后选设备。
- 面板始终常驻、不随开关销毁：实现更简单，但关闭功能的用户也要一直多占一个网页进程。

## 后果

- 正面：拖一次就能发出去，不需要切换窗口；只改 macOS 平台层、一个独立面板和一个设置项，不涉及协议。
- 负面：依赖窗口 delegate 转发拖放的 AppKit 行为，以及 `with_inner_tray_icon` 暴露的 `tray-icon` 内部类型（Tauri 升级小版本时要回归测试）。Windows 的通知区域图标不支持拖放，这个功能只在 macOS 上有。
